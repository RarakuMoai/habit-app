# Habit App 四時段場景系統改良計劃書（FABLE5 執行版）

## 1. 專案目標

讓 App 的主要兔咪場景依使用者所在地的現實時間，自然呈現「早晨／白天／黃昏／夜晚」四個階段。體驗方向可參考遊戲登入畫面隨時間改變所帶來的陪伴感與世界感，但不得直接複製《原神》的構圖、素材、色盤或特效；本 App 應維持自己的兔咪、柔和室內 CG 與習慣養成風格。

本功能不是單純替整張背景套四色濾鏡。每個時段應由環境色、主光方向、室內燈具、窗景、少量動態細節共同表達；沒有窗戶的室內場景也必須成立。

核心成功條件：

- 使用者一眼能感覺時段改變，但文字與功能卡仍清楚可讀。
- 時段交界平滑，不在某一分鐘突然換色或閃爍。
- 切換分頁、App 背景／前景與裝置時間改變後，場景能正確更新。
- 靜置後幾乎不持續耗 GPU；不可為氣氛動畫造成明顯發熱或掉電。
- 保留現有靜態背景作安全回退，功能失敗時不影響 App 操作。

## 2. 現況盤點

目前並非從零開始，已有可沿用的基礎：

- 首頁已有真實時間、連續小時值、窗外天空、日月星雲、室內窗光、塵埃、檯燈光暈與完成特效。
- 共用 `SceneAmbience`／`MascotSceneBackground` 已能把部分效果套到其他頁面。
- 首頁、喝水、計時器、家庭頁已有可挖空的窗景版本；體重與衣櫃頁目前是沒有動態窗景的純室內背景。
- 主要場景圖統一為 1122 × 1402，且共用以螢幕寬度定位的座標系，適合建立一致的素材規格。
- 已有 `RepaintBoundary`、約 30fps 節流、20 秒無操作暫停及不可見分頁停止 ticker 等省電設計。
- 現有全域 `kRoomAmbienceEnabled` 可作緊急回退開關。

目前需要優先修正的結構問題：

- `home_page.dart`、`room_ambient_overlay.dart` 與 painter 各自判斷時段，門檻與色彩並不完全相同。
- 同一場景的窗景、環境光、完成特效可能各持有一個 ticker，造成重複喚醒與繪製。
- painter 在繪製期間直接讀取 `DateTime.now()`；靜態 tint 又可能要等其他 widget rebuild 才更新，時間來源不一致。
- 現行 30fps 對非常緩慢的雲、星光與燈光呼吸仍偏高；許多效果不需要每秒 30 次更新。
- `MaskFilter.blur`、大面積透明疊色及 `BlendMode.plus` 是主要 GPU 風險，應限制範圍與同時存在數量。

## 3. 四時段定義

第一版採固定本機時間，不取得定位、不查日出日落，避免權限、網路、隱私與背景耗電。時間以裝置所在地時區為準。

| 階段 | 核心時段 | 交接區間 | 視覺語言 |
|---|---:|---:|---|
| 早晨 | 06:00–09:30 | 05:30–06:30、09:00–10:00 | 粉金、低角度柔光、清新空氣感、燈光逐漸熄滅 |
| 白天 | 10:00–16:30 | 09:00–10:00、16:00–17:00 | 中性暖白、較高亮度、短而清楚的日光、低彩度陰影 |
| 黃昏 | 17:00–19:00 | 16:00–17:30、18:30–19:30 | 金橘到淡紫、長影、室內燈逐漸亮起 |
| 夜晚 | 19:30–05:30 | 18:30–20:00、05:00–06:30 | 深藍紫環境光、暖色局部燈、低亮度星光或設備微光 |

「核心時段」只決定設計意圖，程式不得使用四個生硬的 `if/else` 瞬切。每種光線都用 0.0–1.0 權重及 smoothstep／curve 混合；交界時允許兩個相鄰階段同時存在。例如 18:45 是黃昏色與夜燈的混合，而不是突然換成夜景。

設定頁應提供：

- `跟隨現實時間`（預設開啟）。
- `固定場景`：早晨／白天／黃昏／夜晚，兼顧輪班、偏好與截圖。
- `省電模式`：自動／省電／完整；第一版可先把 UI 隱藏在功能設定或開發工具，待效能數據穩定後公開。

## 4. 視覺系統

每個場景拆成五層，由下至上固定順序：

1. `Backdrop`：靜態房間 CG 或透明窗洞後的天空。
2. `Environment grade`：全室非常淡的時段色與曝光調整。
3. `Local lights`：窗光、檯燈、壁燈、桌燈、設備微光。
4. `Atmosphere`：極少量雲、星、塵埃或光點，且可完全停用。
5. `Characters/UI`：兔咪與功能介面，不可被重色罩壓暗。

色罩只應作用於背景層，兔咪最多接受獨立、較弱的環境光調整，功能卡與文字不可套時段濾鏡。夜晚不是把整頁塗黑；應採「低亮度冷環境＋暖局部光源」，保留溫暖陪伴感。

### 有窗場景

首頁、喝水、計時器、家庭頁沿用 `*_glassless.png`：

- 窗洞後只畫該窗實際能看到的天空，不繪製全螢幕天空。
- 早晨：低位暖日、淡雲，星星完全消失。
- 白天：高亮淡藍天空，雲移動極慢，不必持續 30fps。
- 黃昏：金橘近地平線、上方淡紫，太陽下降，室內燈開始亮。
- 夜晚：深藍天空、少量固定星點、月亮或雲緩移；避免大量粒子。
- 日月位置可依時間插值，但不必做天文正確模擬。

### 完全室內、沒有窗外的場景

禁止為了顯示時間而硬加不合構圖的窗戶。以「室內物件和光源狀態」表達時段：

- 體重頁：早晨採清爽暖白頂光；白天中性自然光；黃昏用側向金橘反射；夜晚用低亮度冷環境光＋秤面或小夜燈的微光。
- 衣櫃頁：早晨偏奶油金；白天保持服裝顏色最準確；黃昏增加柔和長影；夜晚以鏡前燈／衣櫃燈形成暖色局部光，不整體染藍到影響試衣判斷。
- 可用鐘面亮度、桌燈、牆面反光、地板陰影長度、背景小物狀態傳達時間，但第一版每房只選 1–2 個訊號，避免畫面忙亂。
- 若現有背景沒有可合理發光的物件，先只做環境色與靜態局部光，不新增突兀道具。

### 兔咪與時段的關係

第一版不需要為四時段各生成一張兔咪素材。保持既有核准 PNG 與輕量呼吸／位移演出：

- 夜晚可降低呼吸速度、減少眨眼頻率或優先選用既有 `tumi_night`／`tumi_sleep`，但不能覆蓋由任務狀態觸發的開心、難過等高優先級表情。
- 時段只是一個低優先級情境；使用者完成習慣的即時回饋永遠優先。
- 不在兔咪臉上畫假眨眼或嘴型；若未來需要新的睡意差分，另走核准 PNG 差分流程。

## 5. 技術架構改造

### 5.1 建立單一時間模型

新增建議檔案：

- `lib/utils/scene_time.dart`
- `lib/widgets/scene_ambience.dart`（可由現有檔案逐步搬移，不要求一次大改名）
- `test/scene_time_test.dart`

核心型別建議：

```dart
enum ScenePeriod { morning, day, dusk, night }

class SceneTimeState {
  final DateTime localNow;
  final ScenePeriod dominantPeriod;
  final double morningWeight;
  final double dayWeight;
  final double duskWeight;
  final double nightWeight;
}

class SceneTimeController extends ChangeNotifier {
  SceneTimeState get state;
  void refresh();
  void setPreviewHour(double? hour);
}
```

要求：

- App 可見時只保留一個 controller，所有場景讀同一份 state。
- 時段權重正常情況每 60 秒更新一次即可，不需逐幀讀系統時間。
- App `resumed`、系統時區／日期可能改變、設定切換固定時段時立刻 `refresh()`。
- debug 預覽沿用現有小時覆寫，但改由 controller 注入，不保留散落的全域判斷。
- `home_page.dart` 的背景 gradient、accent、tint、窗景與 painter 全部讀同一份權重。
- 完成所有習慣的綠色慶祝主題應疊加在時段之上，不可取代時間狀態。

### 5.2 單一場景動畫時鐘

同一個可見場景只允許一個動畫 clock/listenable，窗景、室內光與完成特效共享相位：

- 預設完整模式最高 20fps；只有短暫互動慶祝可在 1–2 秒內提高到 30fps。
- 省電模式最高 10–12fps，雲、星與塵埃可直接停止，只保留時間漸變與兔咪必要動畫。
- 無操作 10 秒後先降到 5fps 或靜態；20 秒後完全停止 ticker。使用者觸碰才喚醒。
- `TickerMode` 關閉、App 不在前景、頁面不可見時必須為 0fps。
- 時段權重更新不應喚醒永久動畫；ticker 停止時仍可單次 repaint 更新正確色彩。

不要讓每一層各自建立 `Ticker`。將 `WindowBackdropPainter`、`RoomAmbientPainter`、`RoomSceneEffectsPainter` 改成共享 `SceneAnimationClock` 的 `Listenable`，或合併能安全合併的 painter。

### 5.3 場景設定資料化

擴充 `SceneAmbience`，避免每頁自行寫判斷：

```dart
class SceneAmbience {
  final Rect? windowRect;
  final String? glasslessAsset;
  final List<SceneLight> lights;
  final SceneQualityPolicy quality;
  final bool preserveColorAccuracy; // 衣櫃頁為 true
}
```

每頁只描述「窗在哪裡、燈在哪裡、哪些效果允許」，時段算法與效能規則集中在共用層。座標一律使用 1122 × 1402 圖片的比例座標，禁止直接寫特定手機像素。

## 6. 素材策略

第一階段不製作四張完整背景，優先採「一張核准背景＋透明窗洞＋程式光影」。這能減少包體、記憶體與跨時段跳圖，也最容易維持場景一致。

### FABLE5 與生圖工作的先後順序

本項目預設由 **FABLE5 端到端負責**：先改程式，也可以在程式原型完成後自行製作必要的局部圖片。若 FABLE5 的生圖／修圖未通過品質驗收，再把該張素材轉交給我，或由使用者主動處理。不要在程式原型完成前，預先生出每個房間的四張完整時段背景。

固定工作流程：

1. FABLE5 先完成 Phase 0／1：效能基準、單一時間引擎、四時段權重與預覽功能。
2. FABLE5 使用現有首頁背景完成早晨、白天、黃昏、夜晚的程式光影原型。
3. FABLE5 輸出 06:30、12:00、17:30、22:00 四張相同裝置尺寸的首頁截圖，並附上 profile 數據。
4. FABLE5 先自行檢視四張截圖，逐項標記：
   - `保留程式效果`：天空、色溫、簡單光束與小範圍光暈已自然。
   - `調整程式參數`：只需要修改顏色、透明度、位置或速度。
   - `需要局部生圖`：家具遮光、複雜投影、燈具真正發亮等程式難以自然呈現的區域。
5. FABLE5 可先針對第三類自行製作同畫布透明 PNG overlay，必須採局部編輯，不改動原始背景的家具、構圖與畫風。
6. 使用者檢查 FABLE5 產出的 overlay：通過就由 FABLE5 直接接入；不通過才轉交給我重做／修正，或由使用者主動提供素材。
7. FABLE5 將核准 overlay 接回 `SceneAmbience`，再執行效能與四時段 golden screenshot 驗收。
8. 首頁通過後，才用相同流程逐頁處理喝水、計時器、家庭、衣櫃與體重場景。

分工原則：

| 工作 | 負責方 | 原因 |
|---|---|---|
| 時段判斷、平滑混色、狀態管理 | FABLE5 | 必須由單一程式架構保持全 App 一致 |
| 窗外天空、日月、星點、慢雲 | FABLE5 | 適合局部程式繪製，檔案小且可連續變化 |
| 簡單窗光、色罩、radial light | FABLE5 | 容易調參，無須增加大型圖片 |
| 複雜家具遮擋與自然投影 | FABLE5 先做；未過驗收再轉交我／使用者 | 靜態透明差分通常比每幀 blur 更自然、更省電 |
| 燈罩發亮、電子鐘、鏡前燈等物件狀態 | FABLE5 先做；未過驗收再轉交我／使用者 | 需要保持既有 CG 結構與材質一致 |
| Overlay 接入、品質降級與效能測試 | FABLE5 | 屬於 Flutter 實作與裝置驗收 |
| 兔咪夜晚／睡意新差分 | FABLE5 可先做；未過驗收再轉交我，使用者最終核准 | 必須使用核准底圖做局部差分，保留兔咪身份 |

FABLE5 生圖／修圖的通過標準：

- 必須把原始圖片視為 edit target，採 local edit；不得整張重畫。
- 畫布尺寸、構圖、家具位置、透視、色盤與 CG 質感保持不變。
- 未指定修改的區域不可漂移，尤其是窗框、桌腳、燈具輪廓與兔咪位置。
- Overlay 背景必須透明、邊緣乾淨，不能有白邊、黑邊、半透明髒污或接縫。
- 疊回原圖後在窄／寬螢幕均像同一個房間，不可看起來像另一張重畫版本。
- 夜間效果不可壓暗 UI 或破壞衣櫃頁的服裝色彩辨識。
- 使用者對前後對照圖有最終核准權；未核准素材不得進入正式資產。

若任一項不合格，FABLE5 不應反覆整張重生。先嘗試一次更精準的局部修正；仍不合格就保留程式效果並把該素材需求、原圖、修改範圍和失敗版本一起交給我或使用者處理。

禁止事項：

- 不得先生成「6 個房間 × 4 時段」共 24 張完整背景。
- 不得把現有背景只當風格參考，再重畫一個相似房間。
- 不得在沒有 FABLE5 原型截圖前猜測所有燈光差分需求。
- 不得為了顯示時段，在無窗房間硬新增窗戶或不合理道具。
- 若程式效果只需調色或移動位置即可修正，不得用生圖取代程式調整。

只有以下情況才新增差分圖：

- 夜晚必須開燈，但原圖燈具無法用程式光暈自然呈現。
- 黃昏的固定長影牽涉複雜家具遮擋，CustomPainter 看起來像貼上去。
- 某個物件需要真正改變狀態，例如燈罩發亮、電子鐘亮起。

差分優先做小尺寸透明 overlay，而不是再輸出一張 1122 × 1402 全圖。命名建議：

```text
assets/scenes/<room>/<room>_light_morning.png
assets/scenes/<room>/<room>_light_dusk.png
assets/scenes/<room>/<room>_light_night.png
```

所有 overlay 必須與底圖同畫布、同構圖、透明背景，未改區域完全透明。若修改兔咪既有素材，必須使用局部差分流程，不得重畫整張兔咪。

圖片載入要求：

- 不同時把四張全尺寸背景常駐記憶體。
- 只預載當前與下一相鄰時段需要的 overlay。
- 確認 Flutter 實際解碼尺寸接近顯示需求；2x／3x 資產依裝置密度規劃，避免低階機解碼過大圖。
- 新增素材前記錄 APK/IPA 包體增量與解碼後記憶體；單張 1122 × 1402 RGBA 解碼約 6 MB，不可無限制複製。

## 7. 效能與省電硬性規範

### 繪製規範

- 大面積 blur 每個場景同時最多 2 個；能用預模糊 PNG／radial gradient 就不要每幀 `MaskFilter.blur`。
- 固定陰影、光池與 vignette 畫入靜態 overlay 或快取成 `Picture`，不每幀重算 Path／Gradient。
- 粒子數完整模式每場建議不超過 12，省電模式為 0；粒子位置陣列預先建立，不在 `paint()` 中配置新 List/Path。
- 動畫只畫在窗洞或局部燈光矩形，避免 full-screen saveLayer。
- 背景、動態光、兔咪、UI 各自有清楚的 `RepaintBoundary`，但不要碎成大量無意義 layer。
- 靜態 widget 不標 `willChange: true`；只有動畫期間才標示會變動。
- 不使用持續的 `setState()` 驅動整頁；以 painter repaint listenable 只更新必要圖層。

### 執行狀態規範

- App lifecycle 為 paused/inactive/detached：停止所有場景 ticker 與 timer。
- 非目前分頁：停止 ticker，不靠 opacity 隱藏後繼續跑。
- 開啟鍵盤、bottom sheet 或全螢幕 dialog 時，底層場景可直接暫停。
- 系統「減少動態效果」開啟時，使用靜態場景並只在分鐘更新時做一次無動畫換色。
- 低電量模式若 Flutter／平台層可可靠取得，降為省電品質；若第一版不接平台 API，至少提供 App 內手動省電模式。

### 建議品質分級

| 品質 | FPS | 動態內容 | 適用情境 |
|---|---:|---|---|
| 靜態 | 0 | 單次時間配色、固定燈光 | 減少動態、背景、不可見、20 秒閒置後 |
| 省電 | 10–12 | 燈光慢呼吸；無粒子、雲固定 | 使用者選省電、較弱裝置 |
| 完整 | 20 | 慢雲、少量星／塵埃、局部燈光 | 前景且剛互動 |
| 短暫慶祝 | 30，最長 2 秒 | 完成星光／彈跳 | 完成習慣後立即回饋 |

## 8. 分階段執行順序

### Phase 0：建立基準，不改視覺

1. 在目前版本用 profile/release 建立首頁 60 秒前景、60 秒靜置、快速切六個分頁的效能基準。
2. 記錄 frame raster/UI time、掉幀、GPU 使用、CPU 喚醒、記憶體及 10 分鐘耗電趨勢。
3. 以 iOS Instruments Energy Log／Core Animation 與 Android DevTools／Perfetto 擇實際平台測量；不可只看 debug 模式。

完成標準：已有可重現的測試腳本、裝置型號、OS、build mode 與數據表。

### Phase 1：統一時間引擎

1. 實作 `SceneTimeController`、四權重與固定時段預覽。
2. 合併首頁和共用環境層的門檻、色盤與時間來源。
3. 加入分鐘更新、App resume 更新、跨午夜與 debug override 測試。
4. 保留 `kRoomAmbienceEnabled` 回退。

完成標準：所有頁在同一預覽小時顯示相同時段；05:30、06:00、09:30、16:30、18:30、19:30、23:59、00:00 無跳色。

### Phase 2：首頁做為 Golden Scene

1. 先只把首頁四時段完成到可定稿品質。
2. 共用單一動畫 clock，完整模式降到 20fps。
3. 修正窗光、地板影、檯燈與兔咪色溫的層級，不讓 UI 染色。
4. FABLE5 先輸出 06:30、12:00、17:30、22:00 四張程式原型截圖，不等待生圖。
5. FABLE5 依四張截圖判斷是否需要局部透明 overlay；不需要就維持純程式方案。
6. 若需要，FABLE5 可先生圖／修圖並提交前後對照；未過品質驗收才轉交給我或由使用者處理。
7. FABLE5 接入核准 overlay，並以相同四個時間重新產生 golden screenshot 驗證。

完成標準：設計確認四張基準圖；靜置 20 秒後場景 0fps；效能不劣於 Phase 0。

### Phase 3：推廣到有窗場景

依序做喝水 → 計時器 → 家庭：

1. 校正每頁 `windowRect` 與光源位置。
2. 共享天空與時間模型，但每頁保留自己的室內燈配置。
3. 逐頁做四時段截圖與窄／寬螢幕檢查。

完成標準：窗框無漏光、天空不蓋住室內、各頁切換時時段一致，離頁後 painter 不再更新。

### Phase 4：完成無窗室內場景

依序做衣櫃 → 體重：

1. 不加假窗，先用環境 grade、燈具光與陰影表達時段。
2. 衣櫃開啟 `preserveColorAccuracy`，白天幾乎不染色，夜晚也保持服裝可辨識。
3. 視覺仍不足時，才申請 1–2 張局部透明燈光 overlay。

完成標準：關閉所有動畫時仍能分辨四時段；衣服與數據的辨識度不下降。

### Phase 5：效能收斂與正式開關

1. 實作靜態／省電／完整／短暫慶祝品質切換。
2. 測量低階與主力 iPhone／Android 各至少一台；包含 10 分鐘停留及頻繁切頁。
3. 加入遠端或本機 feature flag（若專案尚無遠端設定，先保留本機總開關）。
4. 小比例開啟後觀察 crash、卡頓與使用者回饋，再設為預設開啟。

## 9. 測試與驗收清單

### 功能

- 四時段預覽與真實時間結果一致。
- App 停在前景跨過交界，最多 60 秒內自然更新。
- App 背景後修改系統時間／時區，再回前景立即正確。
- 固定場景不受真實時間改變；恢復自動後立即同步。
- 跨午夜、夏令時間地區、12/24 小時顯示設定均不影響計算。

### 視覺

- 06:30、12:00、17:30、22:00，每個場景各一張基準圖。
- iPhone SE 類窄畫面、主力大螢幕、Android 長螢幕與橫向退化畫面不漏光／錯位。
- 文字對比、卡片、AppBar、兔咪臉部不被夜色罩壓暗。
- 黃昏到夜晚連續預覽 30 秒無閃爍、色階 banding 或突然亮燈。

### 效能

- profile/release 測試；debug 數據不作上線判斷。
- 前景完整模式在目標 60/120Hz 裝置不因場景層產生持續 jank。
- 靜置 20 秒後場景 ticker 為 0，畫面不持續 repaint。
- 非目前分頁與 App 背景時場景 CPU/GPU 活動接近 0。
- 與 Phase 0 相比，10 分鐘停留的耗電、溫度與記憶體不得明顯惡化；若無法達成，預設改為省電模式並移除高成本效果。
- 建議工程門檻：場景額外平均 raster cost 盡量低於 2 ms；動畫期間無連續 5 個以上超過 frame budget 的 raster frame。

## 10. FABLE5 實作限制與交付格式

執行時請遵守：

- 先完成 Phase 0／1，不要直接大量生四套背景圖。
- 每個 Phase 各自提交小範圍 commit；不得混入使用者工作樹中無關的既有修改。
- 每次修改附：變更檔案、前後截圖、profile 數據、已知限制與回退方式。
- 不移除現有靜態背景；所有新效果都能由總開關關閉。
- 不把《原神》素材、UI、天空構圖或特效直接搬入專案。
- 修改音訊時遵守既有 BGM 規則；本計劃第一版不要求新增時段 BGM，避免額外耗電、版權與播放狀態複雜度。
- 若要新增或修改兔咪 PNG，只做核准底圖的局部差分，保持身份、比例、構圖與 CG 質感。
- 完成 Dart 修改後執行格式化、靜態分析、相關單元／golden 測試及 `scripts/check_units.sh`。

每一階段回報模板：


## 11. 最小可行版本（MVP）界線

第一個可上線版本只需要：

- 單一可靠的四時段時間引擎。
- 首頁四時段定稿。
- 其他房間至少有一致的靜態時段 grade；有窗頁可顯示相同時段天空。
- 20 秒閒置 0fps、離頁 0fps、App 背景 0fps。
- 固定場景預覽與一鍵總回退。

天氣、季節、真實日出日落、地理位置、四時段 BGM、更多兔咪差分都留到後續版本。先把「時間一致、畫面舒服、不耗電」做穩，再增加世界感。
