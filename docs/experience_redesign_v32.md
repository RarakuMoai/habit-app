# V3.2：超慢跑 BPM 精簡布局

> 本文件記錄V3.2。使用者後續偏好V3.1收合分區，最新控制形狀與底部留白見 [V3.3](experience_redesign_v33.md)。

基準：`6d79c63`（V3.1）；沿用 `codex/experience-redesign` 與獨立 `redesign` flavor。
使用者回報超慢跑 BPM 仍造成錯位，希望減少占用空間，同時保留完整功能。

[原生前後比較](../design_trials/experience_redesign/review_v32/index.html#comparison)

## 根因與修正

V3.1 已固定左右欄寬，但 BPM 仍插在開始與重設之間。右側操作區從其他運動的
104pt 增加到156pt；整組垂直置中後，開始往上26pt、次要操作往下26pt。
這是額外資訊列改變整組高度，不能再靠移動 offset 或縮小面盤解決。

- **BPM 使用既有標題列**：左方44pt高、最大196pt寬的膠囊，與右方設定在同一列；不再增加主操作區高度。
- **主要位置一致**：開始52pt、間隔4pt、次要操作48pt，共104pt；面盤與操作欄維持44：56。切換運動時開始與重設保持同一位置。
- **完整調速**：左右加減1 BPM、長按連續調整、放開停止，範圍30–240；點數字開啟精準輸入，取消不改值、超出範圍明確提示，確認後保存。運動中仍可即時調整。
- **減少重複內容**：BPM 已在上方可讀可調，面盤待機顯示「超慢跑／30分」，運動時保留倒數與「保持節奏」；階段語意與既有擺錘持續保留。
- **觸控與字級**：加減各44×44pt，不使用 FittedBox 縮小整組；上方剩餘寬度不足時，數字與單位改兩行。極矮面板仍使用摘要及捲動，BPM 接在主要操作後、快捷前，避免壓縮熱區。

原生驗證另發現，鍵盤會使房間版切換到摘要版，原本開啟輸入框的 BPM widget
因此被重建。確認結果改由穩定的 `ExerciseTimerState` 承接；僅在頁面仍掛載且仍為
超慢跑時套用，避免輸入後沒有生效。計時引擎、儲存鍵與音訊排程維持既有邏輯。

## 驗證

- 靜態分析無問題；相關計時布局／BPM測試34項通過。
- 完整回歸 **966項全部通過**；獨立Release（142.5MB、arm64）建置並驗簽通過，使用既有Apple Development簽章供本機測試。產物雜湊見[驗證紀錄](../design_trials/experience_redesign/review_v32/validation.json)。
- 真實 `MainPage` 約束的 widget 測試：320×667／430×932、繁中／英文、1.3倍字級，包含300pt鍵盤遮擋、範圍錯誤、取消、確認、長按上下限，以及五種運動切換的主操作Y座標。
- 幾何回歸先在V3.1執行，四個布局案例皆因BPM仍在操作區而失敗；V3.2通過。
- 專用iPhone14ProMax／iOS26.5模擬器，430×932、繁中、預設字級、正常動態，13張原生畫面通過並逐張檢視。包含待機、加減、精準輸入、準備、運動中調整、暫停與展開；以Tabata為對照，量測開始位置相同。
- 使用記憶體測試資料；排除通知授權與超慢跑音訊。原生輸入框截圖保留鍵盤造成的布局變化，但Flutter截圖本身不包含系統鍵盤畫面。實機音訊、觸覺與Release流暢度由本人確認。

## 本人試用

先比較收合超慢跑與Tabata的開始／重設位置，再試「加減→長按→點數字→確認」，
確認數字好讀、按得到、輸入確實生效；運動中再次調整BPM，最後展開比對。
這輪不代表整體視覺已獲驗收，其餘主頁沿用先前方向。
