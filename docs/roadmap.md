## 0. 一句話與目標

- **產品**：一人開發的「習慣陪伴」app。兔咪安靜陪使用者把每天的小事做完，不監督、不評分。
- **商業目標**：養活自己，約 **$2k MRR**（當路標，不當預期 — 多數訂閱 app 終身 < $1k MRR）。
- **心態**：興趣專案、重程式品質與長期可維護、沒有硬性上架時程；但**變現有階段閘門，數據不過不前進**。

## 1. 定位與原則（紅線）

- 兔咪是**陪伴者**，不是教練/老師/管理員。
- **核心習慣追蹤永遠免費且大方**（習慣數不限或大方上限）。
- **裝飾/金幣是「免費留存引擎」，不是商品**（學 Finch，$30M ARR 驗證）。
- **永不放廣告**（毀陪伴感）。
- 不做純買斷（天花板低）、不做純裝飾 IAP（收不到錢）。

## 2. 變現模式（定案 2026-06-12）

- 收入 = **訂閱**：年 **$14.99–19.99**（主推）/ 月 $2.49 / 終身 $39.99。便宜訂閱是一人開發的優勢。
- 訂閱賣「深度」，轉換力排序：
  1. **雲端同步/備份**（安全感，最強賣點）
  2. 完整統計 / 匯出
  3. 訂閱限定裝飾組 + 主題皮膚 + 劇情包
  4. Widget / 家庭擴充
- 原則：**免費版是完整遊戲，訂閱賣「更多你已愛上的東西」**。「支持一人開發者」的真誠敘事是陪伴系 app 的加分。
- **訂閱的具體內容不現在猜** — Phase 0 埋本機匿名使用統計，Phase 1 用數據挑「最受歡迎功能的加深版」。

## 3. 裝飾系統 —「整單元替換」哲學

核心原則：**換整個成品，不疊層、不去背**。背景與造型都套用同一邏輯。

### 3a. 背景（定案 2026-06-12）
- 每個頁面（首頁/喝水/番茄鐘/體重）背景可換，**商品 = 一張完整背景圖**。
- 零拆層、零透視/去背風險；每月上新成本 = 生幾張圖，完美配訂閱的持續供新。
- 免費層：現有背景 + 2–3 張金幣解鎖（保住金幣賺取/消耗迴圈，兼當訂閱試吃）。
- 訂閱層：整庫任意換 + 每月上新 + 季節限定。

### 3b. 衣櫃 / 兔咪造型（方向更新 2026-06-16）
- 做法：**整套替換**。每一套造型用 AI 生**一整組**兔咪圖，**整套不可拆**，動作/姿勢差異無所謂（因為整套一起換）。
- **張數先不定**：先把核心（目前 8 張情緒差分）打磨到「近乎完美、可上架」程度，屆時自然知道一套需要幾張。做造型本身不難（使用者有信心），所以這不是現在的瓶頸。
- **⚠️ 此處取代舊結論**：舊記憶寫「角色換裝會組合爆炸 → 只做房間裝飾」，前提是「逐層/逐情緒人力重畫」。**AI 生圖時代整套重生成本可控，反成最佳解**，故改採整套造型替換。
- 與「**槽位/物件去背裝飾已擱置**」不衝突：那是疊層去背（難、已放棄），這是整套替換（無去背問題）。
- **風險（待驗證）**：AI 跨整套維持「同一角色 + 同一套造型」的一致性。這是這條路唯一的技術風險，不是去背。
- 商業：一套造型 = 一次上新，完美配訂閱節奏。

### 3c. 共用技術
- 前約 10 張資產直接打包（~5MB）；庫變大後用 **Apple On-Demand Resources**（免自架伺服器）。
- 生圖維持**手動 ChatGPT**（用既有訂閱額度，零成本）；量大再開 OpenAI API。管線設計與來源無關。
- 背景生圖用統一模板（地平線 / 兔咪站位淨空區 / 光向）。

## 4. 帳號與同步（定案 2026-06-16）

兩種都要，但**有先後**：

1. **先做 iCloud / CloudKit 同步**（Phase 2）：同一 Apple ID 跨「使用者自己的裝置」同步資料。**零伺服器成本**，且是最強訂閱賣點。
2. **跨平台帳號（Email/Google 登入 + 自架後端）**：未來目標，**等 Android 上架且有收入後再評估**。它需要伺服器與維運，與「一人開發、零成本」策略有張力，所以排在 iCloud 之後。

## 5. 功能藍圖

**已確認會做（基建已鋪好）**
- 積分系統擴展（雲端同步 / 家長報表 / 防竄改）— 寫入已收斂到 `applyPointsBatch` 單一入口。
- 音效 / 震動使用者開關 — 回饋已收斂到 `utils/app_feedback.dart`。
- onboarding 改版（含多語言的語言選擇頁）— 頁面已表格化，有全流程測試。

**多語言發行（未來）**
- 目前字串全是硬編碼繁中。新字串朝 i18n（ARB / flutter_localizations）靠攏；UI 排版預留長字（英/德比中文長）；暱稱等字數上限放寬。
- 發行順序：中英先行，**日文優先**作為第一個擴充語言（Phase 3）。

**待議分頁**（`debug_fake_tabs.dart` 內的 placeholder：衣櫃 / 記帳 / 商城 / 任務 / 統計）
- 衣櫃 → 已升級為 §3b 的造型系統。
- 商城 / 任務 / 統計 → 與訂閱、留存、裝飾相關，納入 Phase 1–2 規劃。
- **記帳（確定要做，輕量版，範圍待對齊）**：使用者確定想做輕量版，但「輕量」的具體界線還沒和開發對齊。**絕不做完整記帳 app**（多帳戶/分類/預算/報表＝偏離陪伴定位、一人開發負擔重）。分級提案見 §9，待使用者選一檔。

**不在近期計畫**
- 不新增習慣類分頁；跨頁基建（shell 防爆、單位 listener mixin）等「第三個使用場景」出現再抽。

## 6. 視覺與呈現方向

- **兔咪**：CG 差分立繪 + Flutter 輕量動效 + AI 生圖。**不走 Rive / 骨架動畫**（2026-06-12 四種向量實驗全部否決、永久封存；骨架級動畫唯一解是未來有收入後外包真人動畫師）。
- **背景**：原 CG 圖不動 + Flutter 動態光影 overlay（晨/晝/暮/夜，連續 hour smoothstep）。**全程序化背景已終止**（媒介極限，幾何拼不出 diffusion 筆觸）。
- **窗外景**：挖透明玻璃 + 墊底 `WindowBackdrop` 畫動態天空（日月/星/雲/灌木）。去背圖逐頁手工/AI 製作（玻璃透明、窗框窗櫺前景物保留）。系統已支援首頁/番茄鐘/喝水/家庭，待去背素材放入即生效。
- **特效全在 Flutter 端**（CG 只畫純角色；彩帶/星星/光暈等 overlay 重用）。
- 視覺 token（暖棕墨色、暖棕雙層陰影、卡片語彙、時段配色）集中在 `lib/utils/app_style.dart`，細節規範見 AI 記憶 `project_visual_design_spec`。
- **上架前待辦**：把 Nunito / Baloo 2 字型打包進 assets（目前是執行期下載）。

## 7. 排程與出口閘門（數據不過不前進）

| 階段 | 期程 | 重點 | 出口閘門 |
|---|---|---|---|
| **Phase 0** 上架前 | ~1–2 月 | 活的兔咪、金幣+每日登入+連勝、背景 v1、中英 i18n+字型打包、埋匿名統計 | 免費上架 |
| **Phase 1** 留存 | 2–3 月 | 劇情事件 v1、節日活動、ASO | **D1>30% / D7>15% / D30>8%** 才進 Phase 2 |
| **Phase 2** 變現 | 1–2 月 | CloudKit 同步 → 訂閱三檔 | 里程碑 **$100 MRR** |
| **Phase 3** 成長 | — | 多語言（日文優先）、季節商品 | $100→$500→$1k→$2k MRR 階梯 |

> 數學備忘：$2k MRR ≈ 1,100+ 訂戶 ≈ 2–4 萬活躍用戶（轉換 2.5–4%），通常上架後 1–3 年。
>
> **最大瓶頸是留存（Phase 1），不是變現方式。** 變現模式已想夠，別過度規劃它。

## 9. 記帳：輕量版分級提案（待使用者選一檔）

使用者確定要做輕量記帳，但「輕量」的界線要對齊。三檔由輕到重：

- **A 級 ·「省錢撲滿」**（最輕，最貼陪伴定位）：不是記帳，是把「省錢」當成習慣/目標。
  設省錢目標（例「少喝一杯手搖＝省 $50」），達成當打卡，累積「總共省下 $X」，兔咪替你開心。
  完全長在現有習慣＋金幣系統裡，幾乎零新資料模型。
- **B 級 ·「每日花費追蹤」**（中，像體重頁）：每天記一個「今天花了多少」總數字，看趨勢圖／月總。
  無分類、無帳戶、無收入；可選每日/每月預算線，超支兔咪提醒。單一數值追蹤，沿用體重頁模式。
- **C 級 ·「簡單收支分類」**（最重，逼近小記帳 app）：每筆記 金額＋分類，月總覽＋圓餅。
  **不建議** — 開始有記帳 app 的形狀，與陪伴定位拉遠、維護成本上升。

> 開發建議：**A 或 B**。A 最貼「兔咪陪你養好習慣」（省錢也是一種習慣），B 是使用者已熟悉的單值追蹤。
