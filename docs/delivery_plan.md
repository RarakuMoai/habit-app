# 工作推進、裝置分工與驗收

更新：2026-09-10。依使用者要求維護全局與下一步，涵蓋體驗、工程、測試版與正式上架。
本頁是可調整的推進建議；已授權的工作持續執行，尚未定案的產品範圍不自行擴張。
發布授權仍依 [AGENTS.md](../AGENTS.md)，公開上架檢查以 [prelaunch_audit.md](prelaunch_audit.md) 為單一來源。

## 回覆與協作方式

每輪開發完成後，依工作量簡短交代：

1. **本輪結果**：完成什麼、在哪個環境驗證、還有什麼限制；區分美術樣品、正式整合、模擬器與實機。
2. **全局位置**：本輪解決哪個主要問題，還有什麼會阻礙下一階段；不只追蹤當前一個小元件。
3. **下一步**：推薦優先一件、必要時最多三件，說明目的及與後續工作關係；有順序，不只羅列可能性。
4. **請使用者驗證**：給可開啟的圖片／影片或已可操作版本、明確操作和觀察點；已知缺陷先標明，避免重複排查。

問使用者時優先問會改變方向的少數問題，例如動作性格、節奏與介面理解程度。
程式檢查、素材完整性、模擬器與可自動化驗證由 AI 處理，不把整套 QA 丟給使用者。
有使用者回饋就更新結果與下一步；沒有回覆只代表尚未驗收，不自動記成通過。
等待美術／實機回饋期間，可繼續已授權且不依賴答案的檢查、工具準備與文件整理。
此要求是每輪工作的習慣，不代表已建立定時提醒或背景自動執行排程。

## 可用設備與任務分工

以下硬體依使用者提供記錄，不推測未提供的規格。

| 設備 | 已知資訊 | 分工原則 |
| --- | --- | --- |
| 目前 Mac | 使用者稱為 Mac NEO；本任務工作區在此 | Flutter 開發、Xcode／iOS 模擬器、介面檢查與整合；可在此完成的輕量素材處理直接做 |
| 另一台 PC | GPU：4070S；系統記憶體：32 GB；CPU：i7-12700KF | GPU 模型推論、動畫生成、渲染或大型批次處理的候選執行設備；具體任務先確認工具相容性與實測需求 |
| 使用者主要實機 | iPhone 14 Pro Max；iOS 與 App 版本依當次回報記錄 | 使用者通常直接用實機，以此作為手感、音訊、效能與外觀的最終驗收；AI 先做程式／素材自檢與模擬器補充檢查，不要求使用者改用模擬器，亦不安裝或啟動實體 iPhone／iPad |

32 GB 是使用者提供的系統記憶體，不能當作 GPU VRAM。第一次需要 PC 執行 GPU 任務時，
再確認實際顯示記憶體、作業系統、驅動、可用儲存空間與操作／連線方式；現在不為了記錄設備先要求安裝整套環境。
知道 PC 存在不等於已連線，也不代表任何模型必定能載入；不先承諾速度或品質。

遇到 Mac 瓶頸時：

1. 先確認是算力／記憶體、平台支援、素材缺件還是演算法／美術問題。換 GPU 不會自動修復不合理的手勢或遮擋。
2. 若是可轉移的運算工作，選一個代表性小樣，準備 PC 任務包：輸入副本、環境檢查、依賴與版本、執行指令、預期產物與驗證方式。
3. 確認可用操作方式後在 PC 執行或由使用者執行任務包，回傳結果、耗時與必要紀錄；不要求使用者自行研究整條管線。
4. 將可用產物帶回 Mac，驗證原圖身份、透明邊緣、尺寸、接縫與 Flutter 實際顯示。保留來源與可重現步驟。

## 現在最需要的使用者回饋

以 **iPhone 14 Pro Max** 為主要實機；換裝與互動操作、回報格式集中在 [實機回饋清單](iphone_feedback_checklist.md)。

- **本輪先驗證睡衣整合**：在衣櫃套用霧藍月牙，返回首頁並聊一段，再完全關閉重開；確認免費、保存正確、各表情不掉回原始造型。也可在衣櫃套用原始兔咪，確認能切回。

- **先看選項按壓回饋**：在首頁聊天模式中按住選項、移開取消、放開選取；確認回饋是否清楚而不誇張，選項是否仍容易點到。先由 AI 提供模擬器結果，再請本人確認觸控手感。
- **再看正式首頁互動**：在包含對話 v1 的版本中，點聊天圖示、選一個回覆、返回功能頁；確認選項是否直覺、主選單消失／恢復是否自然、字幕與 MI 是否舒服。若本人版本尚未包含此功能，先準備對應版本與步驟，不要求驗證未安裝內容。
- **稍後才做效能定案**：互動特效與正式場景整合後，再由使用者做實機 profile／release 的幀率、音訊與耗電比較。現在的 GIF／debug 模擬器結果不當作上市效能結論。
