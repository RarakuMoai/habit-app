# 兔咪陪伴：故事、帳號與內容更新製作藍圖

日期：2026-09-11。狀態：**供討論的第一稿**；現況已核對程式，新增故事與產品安排尚待使用者定向。
本輪是整體改版的規劃延續，沿用 `codex/experience-redesign`，程式基準 `8204087`。
不把草案加入正式角色設定或事件目錄，後續依已確認方向分批實作。

## 建議先做什麼

先確定主要使用者、故事調性，以及帳號要解決的第一個問題。
接著完成「一個事件從遇見到收藏、重新開啟仍記得」的完整樣品；同時定義可備份的資料格式。
雲端第一版以單一使用者備份／換機還原為範圍，家庭多人共同編輯另成一階段。

不需要一次做完大量章節、所有登入供應商、多人同步與遠端更新，才能開始體驗。
每階段都要有真正可操作、可驗收的完成點；帳號畫面完成不等於備份完成，圖片完成也不等於事件完成。

## 啟動入口：保留氣氛，也讓日常操作容易到達

建議首次路徑：

`啟動必要初始化 → 兔咪歡迎／開始一起生活 → 選擇先體驗或登入`

- 先體驗，或登入後確認沒有雲端紀錄：簡短前導 → 房間。
- 登入後已有雲端紀錄：先預覽備份，選擇還原或保留本機；完成資料選擇後進房間，不重跑前導覆蓋既有進度。
- 查詢或還原失敗時保留原資料，提供重試與先離線使用；尚未確認雲端狀態前不自動上傳。

建議回訪路徑：

`啟動必要初始化 → 回到房間／上次可恢復的操作 → 背景檢查備份與可用內容`

- 歡迎頁可以有漂亮封面、輕微演出與「開始一起生活」，可重看；不預設每天都要多按一道開始。
- 新章節到來時在房間顯示封面邀請，使用者點下才開始。沿用「兔咪旁短提示」的既有選擇。
- 登入取消、沒有網路、尚無新內容，都能繼續使用已存在的本機資料。
- 第一章與基本場景內建。後續圖／音訊可按章節下載；下載失敗可重試或稍後，不封鎖喝水與打卡。
- 下載進度只顯示真正的工作量，不加入裝飾性的強制等待。
- 內容資料／美術資源更新與可執行程式分開；App功能變更依商店發布流程。Apple 2.5.2 限制下載會引入或改變功能的程式碼。[官方規則](https://developer.apple.com/app-store/review/guidelines/#software-requirements)

## 帳號：值得做，但目的是保住紀錄

開發測試階段不必先有帳號；準備讓其他人長期使用時，備份與換機還原值得優先完成。
Apple／Google提供登入身分，資料仍需由我們的儲存層與後端保存。

建議畫面提供「使用Apple繼續」「使用Google繼續」「先體驗，稍後綁定」，
最終提供哪些供應商依發布平台決定。設定頁設「帳號與備份」，明確區分未綁定、未備份、備份中、已完成與需要處理。
訪客資料會保存在本機；尚未完成可恢復備份時，不能承諾刪除App／換手機後仍找得回。

### 第一版完整流程

1. 訪客離線開始，完成習慣、產生一段回憶；關閉再開仍保留。
2. 切換前先產生有版本號的本機快照，再於設定登入／綁定並查詢雲端紀錄。全新帳號可上傳訪客紀錄；已有備份則先預覽、選擇還原或保留本機，保存被替換版本後才寫入，並核對完整性。
3. 確認成功後顯示備份時間；登入成功但尚未上傳完成，不顯示「已備份」。
4. 在另一個乾淨模擬器登入同一帳號，預覽備份摘要並還原，核對紀錄與回憶。
5. 取消、斷網、過期登入、重試、中斷後恢復，都不覆蓋原本資料。

### 不能漏掉的資料處理

- 本機訪客ID、後端使用者ID與Apple／Google身分分開；同一位使用者可綁多種登入方式。
- 純本機訪客與後端匿名帳號是兩種實作。保留第一次無網路也能體驗的能力，不因登入SDK初始化而擋住本機使用。
- 訪客綁定全新帳號可以搬入原紀錄；登入已有雲端資料的帳號時，要先比較兩份資料，提供可恢復的選擇。
- 第一版可先採「保留這台／還原雲端」及切換前備份；自動合併另行設計。金幣、兒童積分與已領獎勵不能直接相加。
- 備份範圍明確包含習慣歷史、水、體重、衣櫃、幣、家庭紀錄與故事進度；登入憑證、裝置權限與開發者工具設定不混入內容快照。
- 故事使用穩定ID、版本及閱讀進度；保留既有四則回憶ID和首次解鎖日期，不因換圖或新劇情更新而重置。
- 設計資料刪除、帳號刪除及登出後本機資料如何處理；雲端隔離、權限規則與還原測試必須一起完成。
- 若以親子共用為主，先由成人管理帳號與孩子檔案；是否定位兒童App、目標年齡與市場，會影響正式發布設計，待主要受眾確認。

Firebase官方已提供匿名帳號綁定登入身分的流程，但這不是自動完成整套資料遷移與衝突合併。
目前不鎖定後端供應商；發布平台、資料地區、預算與維護方式確認後再選。
[匿名升級](https://firebase.google.com/docs/auth/flutter/anonymous-auth)、[帳號綁定](https://firebase.google.com/docs/auth/flutter/account-linking)。
Apple對使用第三方登入有等價登入選項條件，提供帳號建立也需要App內帳號刪除；
一般習慣功能則應保留不登入使用。[Apple 4.8及5.1.1](https://developer.apple.com/app-store/review/guidelines/)

家庭多人同步需另處理家庭成員、邀請、家長權限、同時編輯、獎勵判重與離線衝突，
不把目前的本機家長PIN當作雲端權限。

## 故事：先有長期方向，再做一章完整體驗

### 已有設定與尚待決定的界線

目前已確認：兔咪為練習獨立生活與培養習慣而離開家人，使用者搬進牠的新家、成為室友。
牠慢熱、愛睏、善良，也會想家、需要陪伴；使用MI語音與意思字幕，不以失敗或離開責備使用者。
見[角色指南](tumi_character_guide.md)與[室友方向](tumi_roommate_interaction_proposal.md)。

家人的身分、原名、家鄉、離家細節與特殊過去尚未確立。以下章名與物件均是草案，不預先加入悲慘身世。

### 主線方向草案：把日子慢慢住成家

| 章節 | 關係與故事的進展 | 可以穿插的日常 |
| --- | --- | --- |
| 1 這裡也有你的位置 | 從陌生室友變得自在，建立共同生活的小默契 | 紙箱、杯子放哪裡、整理到一半 |
| 2 我也常常做不到 | 看見兔咪自己的小困難與努力，雙方都能給予陪伴 | 早餐的小插曲、找不到的襪子、雨天改計畫 |
| 3 想家的那個晚上 | 逐步理解兔咪為何出發；家人設定確認後才細寫 | 窗邊月光、熟悉的點心或一封信（候選） |
| 4 每個人的步調 | 對完成、休息和期待產生小分歧，再學會溝通 | 有人想安靜、有人想慶祝的一天 |
| 5 一起去看看 | 擴大共同生活的範圍，累積真正屬於彼此的回憶 | 散步、季節、一起準備小事 |
| 6 這裡也是家 | 回看開場的小物與選擇，感受到關係已經改變 | 共同整理回憶、下一段生活的邀請 |

主線依實際相遇與前章完成前進，習慣里程碑提供支線回憶；是否採此安排待使用者確認。
不要求故意缺席才能看主線，也不把連勝失敗設為故事懲罰。日常可以單獨開心，不是每一件事都要講道理或解釋身世。

### 第一章的六段事件草案

1. **搬家第一天**：若新前導已介紹室友關係，首章避免重複介紹；用玄關紙箱和安頓動作建立共同空間。
2. **第一個共同的小事**：兔咪也想做一件小事，使用者可分享自己的習慣或先安頓；不替使用者建立假紀錄。
3. **杯子放哪裡**：一個生活選擇被記住，後續台詞或圖片呼應。
4. **整理到一半**：兔咪自己累了；陪坐或一起收最後一件都能推進。
5. **今天有點想家**：只透露已確認的想家心情，家人細節先留白。
6. **把這一頁收起來**：回看共同留下的痕跡，收進第一章回憶。

### 可先製作的一段樣稿：杯子放哪裡

用途：驗證「事件提示→選擇→記住小事→回憶收藏→重開仍記得」，不是定案台詞。
前提：初遇已完成，使用者在房間且沒有其他對話／報到／計時操作占用；符合條件只出短提示。

| 節點 | 圖與演出 | 意思字幕／操作 | 結果 |
| --- | --- | --- | --- |
| 提示 | 兔咪望向桌邊，短暫邀請 | 「杯子……放哪裡好呢？」；可點入或稍後 | 稍後不算看完，後續仍有機會遇見 |
| 01 | 桌邊兩個杯子，兔咪有點猶豫；短MI疑問 | 「這裡，留給你。」 | 等使用者繼續 |
| 02 | 兔咪看一眼窗邊再看桌面 | 「你喜歡靠窗，還是這邊？」 | 選「靠窗的位置」「放你旁邊」「我晚點再選」 |
| A | 兔咪把杯子輕輕移到窗邊 | 「嗯。早上會先看到光。」 | 保存 `cup_place = window` |
| B | 兩個杯子靠近一些，兔咪微笑 | 「那……我不要放太遠。」 | 保存 `cup_place = beside` |
| C | 兔咪把杯子先收妥 | 「好，我先替你留著。」 | 保持未完成；不寫假選擇 |
| 結尾 | 鏡頭回到桌邊，停一拍 | 「這樣，好像有一點像家了。」 | 完成事件，邀請收進回憶 |
| 回憶頁 | 依選擇使用對應杯子構圖 | 「今天，我們替杯子找到了位置。」「小小的一角，也有你的位置。」 | 收藏首次日期；之後重讀不重發獎勵 |

選擇只需被台詞或一張後續情境圖呼應，不必先讓整個3D房間持久移動家具。
第一個樣品不加入幣獎勵，先驗證關係感和流程。場景需用核准兔咪形象；樣稿中的道具構圖待美術確認。

## 大腳本應包含什麼

大綱負責長期因果與人物變化；每個事件再拆成可實作、可測試的腳本。
至少記錄：

- 章節／事件／節點的穩定ID及版本，前置事件、觸發條件、優先度、冷卻與過期方式。
- 邀請文字、鏡頭、場景、服裝、道具、表情、MI／音效、停頓、意思字幕的中英key。
- 選項ID、下一節點、需要記住的具體事實；完成、取消、稍後、重新開啟的行為。
- 專屬回憶ID、頁圖與旁白、獨立封面、首次日期、未讀／已讀、重播時哪些狀態只讀。
- 未下載素材、無網路、退出、App關閉、重播及舊存檔的回退行為。

「看過邀請」「開始對話」「完成事件」「解鎖回憶」「讀完回憶」分開保存。
章節進度不要從文字、連勝值或登入天數猜測；同一事件重入須能防止重複發獎。
對話與回憶揭曉共用讓位規則，避免一次完成習慣卻連續被兩個全螢幕打斷。

## 圖片、封面與聲音的製作流程

沿用[兔咪差分技能](../.agents/skills/tumi-image-variants/SKILL.md)，先檢視現成核准圖，
標清編輯目標與場景參考。鎖定頭臉、垂耳、身形、服裝與CG風格，以非破壞候選檔保存。
新的情境構圖先做少量小樣，通過同角色／同場景／裁切驗證後再批次延伸。

第一段樣品的素材包：一張章節封面、兩張杯子位置情境圖、必要的既有表情、回憶版面，
再配少量MI、物件輕音與淡入淡出。封面文字由App排版，不烘焙進圖，便於中英與不同尺寸。
成品需檢查圖片解碼、透明邊緣、角色一致性、直向裁切、低動態與靜音狀態。

圖片在製作期產生並驗收，使用者App載入完成素材。先內建樣品，日後內容包才加
版本清單、檔案大小／雜湊、快取、重試和可回退的安裝；已解鎖回憶不因一次下載失敗消失。
不必先批次生成整季所有圖，腳本與封面風格還在調整時，先完成代表性樣品更能控管品質。

## 分階段交付與驗收

| 階段 | 可以驗收的交付物 | 通過條件 |
| --- | --- | --- |
| A 方向與骨架（本輪先做） | 現況盤點、本藍圖、主要受眾與故事方向問題、章節及首段樣稿 | 使用者決定調性與第一個帳號需求，候選世界觀不混成定案 |
| B 一段完整陪伴 | 一段正式腳本、封面與情境圖、提示／互動／保存／回憶重讀 | 看得懂兔咪在做什麼，選擇有回應，退出恢復與重開不丟進度；同步處理七日提示錯配 |
| C 保存與換機 | 版本化本機快照、訪客升級、選定供應商登入、備份／還原／刪除 | 兩個乾淨模擬器驗證同一帳號，斷網與衝突不覆蓋資料；真實授權畫面由本人確認 |
| D 首章擴充 | 六段首章、日常支線、回憶章節與獨立封面 | 每事件均有腳本、素材、狀態與驗收，主線不靠懲罰性條件推進 |
| E 依需求擴展 | 家庭多人同步、後續章節內容包 | 有跨裝置需求與明確內容量後，再完成權限、衝突及下載機制 |

B與資料格式設計可並行；若最急迫的是保住現有紀錄，C的本機匯出／還原先提前。
後端實際啟用前才需要確定專案所有權、平台、授權設定、資料地區及維護預算；本輪不預選付費方案。

## 本輪待使用者決定

已先詢問三項：主要使用者、故事調性、帳號最優先解決的問題。
後續再依答案確認發布平台與年齡範圍、家人是否登場及主線如何解鎖。
回憶沿用角色指南已定案的兔咪聲音與視角；若要改變再另行確認。
一次先決定會改變製作方向的問題，剩餘工程細節由實作方案具體化，不一次要求使用者回答全部規格。
