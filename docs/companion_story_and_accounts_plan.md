# 兔咪陪伴：故事、帳號與內容更新製作藍圖

日期：2026-09-11。狀態：**依主線與前導決策修訂的第三稿**；受眾、備份目的、溫暖調性與三個月成長上限已確認。
主線背景、架空年齡、逐步揭露／CG旁白、劇情略過與每日相處計分已確認；
細節與樣稿集中於[故事方向](tumi_story_direction_v1.md)，好感呈現、缺席規則及房間活動版面仍待討論。
本輪是整體改版的規劃延續，沿用 `codex/experience-redesign`，程式基準 `8204087`。
本輪把使用者指定背景與命名方式同步至角色指南，事件目錄標示規劃；未新增程式或把樣稿當成已實作。

## 已確認方向與優先順序

- 帳號的第一目的為備份與還原，保住長期累積的兔咪關係、紀錄及回憶；家庭多人同步不屬於本輪目標。
- 使用者涵蓋較低年齡到中年，家庭功能讓家長管理小朋友；不是只為孩子設計。具體最低年齡與帳號歸屬日後確認。
- 溫馨、陪伴、感情隨相處變好；希望每日使用約三個月達到成長上限，之後靠節日與偶爾特殊事件擴充。
- 「杯子放哪裡」已撤案。它的情感意義不足，且不適合作為固定場景的新物件示範；不再安排腳本或素材製作。
- [市場研究](companion_market_research_20260911.md)作為機制參考；使用者已提供兔咪受欺負、寵物失去、自責、父母支持獨立與返校的主線，詳細以[故事方向](tumi_story_direction_v1.md)為準。
- 前導改故事性，兔咪介紹本名、可取暱稱，功能預設全開。全開不等於自動建立任務或填入個人資料；既有開關／名字與還原存檔須保留。
- 每天一次相處計進度，主動略過也算；主線與特殊事件可在衣櫃回憶重看，不重複加分。

下一步以版本化本機備份／還原為工程優先，故事同時完成首週事件與不同熟悉階段的反應樣稿。
雲端接上同一份已驗證的保存格式；在讓使用者投入長期培養前，必須有可恢復的存檔流程。
先完成能驗收的首週，再展開三個月內容製作；新故事不直接加入正式角色目錄。

## 啟動入口：保留氣氛，也讓日常操作容易到達

建議首次路徑：

`必要初始化 → 先體驗或登入／還原 → 故事初遇與稱呼 → 習慣主頁`

- 新存檔走故事前導，可略過；功能入口預設全開，教學與真正需要的資料放在首次使用。
- 登入已有雲端紀錄先預覽並還原或保留本機，完成選擇才寫入，不用新前導覆蓋舊進度。
- 故事重看不重設稱呼／功能；查詢失敗仍保留本機資料，尚未確認雲端前不自動上傳。
- 具體前導分鏡及「頁面開啟」與「加入每日習慣」的拆分見[故事方向](tumi_story_direction_v1.md)。

建議回訪路徑：

`啟動必要初始化 → 回到房間／上次可恢復的操作 → 背景檢查備份與可用內容`

- 歡迎頁可以有漂亮封面、輕微演出與「開始一起生活」，可重看；不預設每天都要多按一道開始。
- 新章節到來時在房間顯示封面邀請，使用者點下才開始。沿用「兔咪旁短提示」的既有選擇。
- 登入取消、沒有網路、尚無新內容，都能繼續使用已存在的本機資料。
- 第一章與基本場景內建。後續圖／音訊可按章節下載；下載失敗可重試或稍後，不封鎖喝水與打卡。
- 下載進度只顯示真正的工作量，不加入裝飾性的強制等待。
- 內容資料／美術資源更新與可執行程式分開；App功能變更依商店發布流程。Apple 2.5.2 限制下載會引入或改變功能的程式碼。[官方規則](https://developer.apple.com/app-store/review/guidelines/#software-requirements)

## 帳號：備份是長期陪伴的核心能力

使用者已確認帳號是為了避免遺失長期感情與紀錄。備份／還原提升為長期測試的必要能力；
先完成可用的本機匯出與還原，再接雲端，不能等大量故事製作完才處理。
Apple／Google提供登入身分，資料仍需由我們的儲存層與後端保存。

建議畫面提供「使用Apple繼續」「使用Google繼續」「先體驗，稍後綁定」，
最終提供哪些供應商依發布平台決定。設定頁設「帳號與備份」，明確區分未綁定、未備份、備份中、已完成與需要處理。
訪客資料會保存在本機；尚未完成可恢復備份時，不能承諾刪除App／換手機後仍找得回。

### 第一版完整流程

1. 訪客離線開始，完成習慣、產生一段回憶；關閉再開仍保留。
2. 切換前先產生有版本號的本機快照，再於設定登入／綁定並查詢雲端紀錄。全新帳號可上傳訪客紀錄；已有備份則先預覽、選擇還原或保留本機，保存被替換版本後才寫入，並核對完整性。
3. 確認成功後顯示備份時間；登入成功但尚未上傳完成，不顯示「已備份」。
4. 在另一個乾淨模擬器登入同一帳號，預覽備份摘要並還原，核對紀錄與回憶。
5. 取消、斷網、過期登入、重試、中斷後恢復，都不覆蓋原本資料。

### 不能漏掉的資料處理

- 本機訪客ID、後端使用者ID與Apple／Google身分分開；同一位使用者可綁多種登入方式。
- 純本機訪客與後端匿名帳號是兩種實作。保留第一次無網路也能體驗的能力，不因登入SDK初始化而擋住本機使用。
- 訪客綁定全新帳號可以搬入原紀錄；登入已有雲端資料的帳號時，要先比較兩份資料，提供可恢復的選擇。
- 第一版可先採「保留這台／還原雲端」及切換前備份；自動合併另行設計。金幣、兒童積分與已領獎勵不能直接相加。
- 備份範圍明確包含習慣歷史、水、體重、衣櫃、幣、家庭紀錄與故事進度；登入憑證、裝置權限與開發者工具設定不混入內容快照。
- 故事使用穩定ID、版本及閱讀進度；保留既有四則回憶ID和首次解鎖日期，不因換圖或新劇情更新而重置。
- 設計資料刪除、帳號刪除及登出後本機資料如何處理；雲端隔離、權限規則與還原測試必須一起完成。
- 已確認廣年齡與家庭使用情境。建議由成人帳號保存家庭兒童檔案，首版不另外要求每個孩子註冊；最低年齡、獨立使用與發布市場再確認。

Firebase官方已提供匿名帳號綁定登入身分的流程，但這不是自動完成整套資料遷移與衝突合併。
目前不鎖定後端供應商；發布平台、資料地區、預算與維護方式確認後再選。
[匿名升級](https://firebase.google.com/docs/auth/flutter/anonymous-auth)、[帳號綁定](https://firebase.google.com/docs/auth/flutter/account-linking)。
Apple對使用第三方登入有等價登入選項條件，提供帳號建立也需要App內帳號刪除；
一般習慣功能則應保留不登入使用。[Apple 4.8及5.1.1](https://developer.apple.com/app-store/review/guidelines/)

家庭多人同步需另處理家庭成員、邀請、家長權限、同時編輯、獎勵判重與離線衝突，
不把目前的本機家長PIN當作雲端權限。

## 備份實作前要解決的已知缺口

本輪只做程式盤點，尚未修正下列問題：

1. 多個 store 使用多 key 寫入，`SharedPreferences` 並非全 App 的交易；跨日鎖也未涵蓋購買、家庭與事件。快照要在一致狀態建立，還原須先驗證、保留舊版，再一次切換有效版本。[跨日](../lib/utils/logical_day_coordinator.dart)、[金幣](../lib/utils/coin_service.dart)
2. `StoryStore` 載入會濾掉現行目錄不認識的回憶 ID。先檢查格式／內容版本，不能把新版備份當空資料讀入舊 App；保留未知項目或要求更新。[回憶保存](../lib/utils/story_store.dart)
3. 前導會先寫完成旗標再寫其他資料，換機不可重跑前導來代替還原；關係日期、名字與故事須保留。[前導](../lib/pages/onboarding_page.dart)
4. 備份需包含已刪除習慣的關聯紀錄、發幣判重、家庭票券／撤銷、當日與跨日狀態、計時方案／紀錄、收藏與播放偏好，不能只備份首頁可見值。[資料鍵](../lib/utils/prefs_keys.dart)
5. `UsageStats` 明確只留本機且允許漏寫，不混入雲端內容快照。登入憑證、裝置權限、快取與開發工具另管；家長 PIN／救援資料須訂獨立復原策略，換機不能意外解除家庭保護。[使用統計](../lib/utils/usage_stats.dart)

### 保存與還原的完成標準

- 用合成資料在兩個乾淨模擬器完整往返，核對 ID、日期、筆數、關聯、幣、家庭獎勵與回憶，不只看能否開首頁。
- 打卡／發幣／家庭異動／換日途中建立快照仍一致；中途結束還原，重開只有完整舊版或完整新版。
- 新帳號綁定保留訪客；已有雲端紀錄先預覽。空白重裝、舊裝置遲到上傳、雙機修改與重置不能靜默覆蓋唯一備份。
- 上傳採版本檢查並保留可復原的前版；斷網、登入過期、重試失敗仍有上一份完整備份。顯示最近成功時間與尚未上傳狀態。
- 壞檔、未知新格式不能當成空存檔；跨日／回憶重播／事件恢復不重複發獎或更改首次日期。
- 一般資料重置、雲端備份刪除、帳號刪除分開定義；登入或恢復購買成功不能當成保存成功。

## 故事、相處計分與房間

故事背景、五階段人物進展、前導六段樣稿、共鳴選項、CG與衣櫃回憶，集中維護在[故事方向](tumi_story_direction_v1.md)。
使用者指定的寵物失去與返校不再是未知候選；寵物品種、父母支持與返校安排等細節仍需補齊。

已確認每日一次相處計進度，主動略過也算、重播不重複加分；建議以完成／略過當日相處對話記為一個相處日。
日常台詞池也可提供每日相處，不要求每天有全新主線；從衣櫃回憶回放才是重播。
三個月仍是成長上限，日界線與缺席規則另列，不能把普通開 App 或舊相識天數直接當相處日。
好感顯示尚待決定；目前建議關係階段＋相處天數，精確分數隱藏。

「略過劇情」可推進並解鎖回憶，標未讀；「稍後再聊」保留節點，不等同完成。
收束前置可透過讀完或明確略過處理，不強迫閱讀。未選個人化回答不自動補成使用者選擇。
回憶分類為主線／特殊事件；支持全頁CG與兔咪旁白，重看不改進度、首次日期或獎勵。

現有相伴天數是日曆天、幣連勝可重置、使用統計可漏寫，都不能直接當新進度。[相伴天數](../lib/pages/mascot_profile_page.dart)、[登入獎勵](../lib/utils/coin_service.dart)
版本化存檔需保存角色ID、相識日期、規則版本、已計入的相處日、節點／選擇／略過／未讀與首次日期。
舊使用者保留證據；沒有可靠歷史不能虛構90日完成，也不直接清零既有收藏。

房間單一位置是使用者正在考慮的方向，候選以習慣頁保底、固定可見面入口、關功能回家、主線不綁選用功能。
目前七處場景共用人格但沒有位置；面板與語音也須一起修改。細節與可驗證失效情境見故事方向，不只隱藏圖片。
成熟後保留生活、回憶與節日，不讓返校導致角色永久消失。

## 大腳本應包含什麼

大綱負責長期因果與人物變化；每個事件再拆成可實作、可測試的腳本。
至少記錄：

- 章節／事件／節點的穩定ID及版本，前置事件、觸發條件、優先度、冷卻與過期方式。
- 邀請文字、鏡頭、場景、服裝、道具、表情、MI／音效、停頓、意思字幕的中英key。
- 選項ID、下一節點、需要記住的具體事實；完成、取消、稍後、重新開啟的行為。
- 專屬回憶ID、頁圖與旁白、獨立封面、首次日期、未讀／已讀、重播時哪些狀態只讀。
- 未下載素材、無網路、退出、App關閉、重播及舊存檔的回退行為。

「看過邀請」「開始對話」「完成事件」「解鎖回憶」「讀完回憶」分開保存。
章節進度不要從文字、連勝值或登入天數猜測；同一事件重入須能防止重複發獎。
對話與回憶揭曉共用讓位規則，避免一次完成習慣卻連續被兩個全螢幕打斷。

## 圖片、封面與聲音的製作流程

沿用[兔咪差分技能](../.agents/skills/tumi-image-variants/SKILL.md)，先檢視現成核准圖，
標清編輯目標與場景參考。鎖定頭臉、垂耳、身形、服裝與CG風格，以非破壞候選檔保存。
新的情境構圖先做少量小樣，通過同角色／同場景／裁切驗證後再批次延伸。

首週樣品先用現有場景與表情，驗證關係差異；選定有情感意義的關鍵事件後，再做封面與事件圖小樣，
配少量MI、合適的環境音與淡入淡出。封面文字由App排版，不烘焙進圖，便於中英與不同尺寸。
成品需檢查圖片解碼、透明邊緣、角色一致性、直向裁切、低動態與靜音狀態。

圖片在製作期產生並驗收，使用者App載入完成素材。先內建樣品，日後內容包才加
版本清單、檔案大小／雜湊、快取、重試和可回退的安裝；已解鎖回憶不因一次下載失敗消失。
不必先批次生成整季所有圖，腳本與封面風格還在調整時，先完成代表性樣品更能控管品質。

| 階段 | 交付物 | 通過條件 |
