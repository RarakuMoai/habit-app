# FABLE5 任務書：遊戲計時器易用性與可靠性改善

## 文件定位

這是目前已完成之「計時 > 遊戲 > 兔咪遊戲桌」的下一輪改善任務書。

- 現有功能已經可以使用，不是從零重建。
- 本輪先改善設定頁的理解成本、玩家排序，以及對局可靠性。
- `docs/fable5_game_timer_rebuild_plan.md` 是歷史重建文件，不是本輪實作規格。
- 現有程式碼與本文件才是本輪判斷依據。
- 不要求 FABLE5 無條件照做；如果有更好的方案，應先提出比較與理由，讓使用者選擇後再實作。

## 本輪工作方式：先提案，確認後才寫程式

FABLE5 第一次回覆時請不要直接修改程式碼，先完成：

1. 讀完本文件列出的必要檔案。
2. 驗證本文指出的問題是否與目前程式一致。
3. 提出推薦方案、至少一個替代方案，以及各自的取捨。
4. 用簡單文字 wireframe 說明新版設定頁資訊順序。
5. 列出預計修改的檔案、測試、風險與不會動到的範圍。
6. 如果認為本文方案不是最佳解，主動提出更好的方案，不要為了服從文件而做較差的設計。
7. 等使用者選擇或確認後，再開始實作。

## 問題一：玩家排序的指示與實際操作不一致

目前設定頁顯示：

> 由上到下輪流出場，按住 ≡ 拖曳調整

但實際行為是：

- `ReorderableDragStartListener` 只包住右側 `Icons.drag_indicator_rounded`。
- 使用者必須碰右側圖示才能直接拖曳。
- 長按玩家名稱或整列不會拖曳。
- 文案中的 `≡` 與畫面實際圖示也不是相同圖案。

這不只是文案小錯，而是操作承諾與實際命中區不一致。必須同步修正文案、圖示、手勢和無障礙提示，不能只換其中一項。

## 玩家排序方案

### 方案 A：沿用習慣頁的混合排序模式（推薦）

一般狀態：

- 玩家列保持乾淨，不常駐容易誤解的小拖曳圖示。
- 點玩家名稱仍可快速改名。
- 右側使用 `⋯` 選單，內容為「改名／移動／移除」。
- 長按整個玩家列约 1 秒，可用同一個手勢直接拖曳並進入排序模式。
- `⋯ > 移動` 是不知道長按手勢之使用者的明示入口。

排序模式：

- 玩家列進入輕微抖動或其他清楚但不過度的編輯狀態。
- 整列可立即拖曳，不需要再次長按。
- 暫時隱藏或停用改名、刪除等非排序操作，避免誤觸。
- 「出場順位」標題右側顯示清楚的「完成排序」。
- 說明文字改為「拖曳玩家調整出場順位」。
- 棋鐘模式清楚標示前兩位「上場」，其餘為「候補／本局輪空」。
- 排序完成後立即保存，維持目前即改即存的原則。

不建議直接複製習慣頁底部綠色完成列，因為遊戲設定頁底部已經有「完成」與「開始對局」固定列，再加一條底部操作列容易互相競爭。較適合把「完成排序」放在「出場順位」區段標題右側，或在排序模式中暫時替換該區說明。若 FABLE5 有更清楚且不衝突的做法，可以提案。

### 方案 B：明確的「排序／完成」模式

- 在「出場順位」標題右側常駐「排序」。
- 點擊後才進入可拖曳狀態。
- 不支援一般狀態長按拖曳。
- 優點是最容易理解、較少手勢衝突；缺點是熟悉使用者多一步。

### 方案 C：維持拖曳把手，但修正提示

- 保留目前只有右側把手能拖的行為。
- 圖示、文案與無障礙提示完全一致，例如「拖曳右側把手調整順位」。
- 實際命中區至少 44–48 px。
- 實作量最小，但與習慣頁互動不一致，也沒有解決設定列圖示過多的問題，因此不推薦作為首選。

FABLE5 可以提出方案 D，但必須說明為什麼比 A 更適合 2–6 人、位於長設定頁中的短名單。

## 問題二：設定頁一次顯示過多內容

目前完整設定頁會連續出現：

1. 兔咪邀請橫幅。
2. 本局摘要。
3. 常用組合。
4. 玩法。
5. 出場順位。
6. 計時制、回合時間或總時間。
7. Fischer 加秒。
8. 倒數提醒與自動換人。
9. 常用玩家。
10. 底部完成與開始對局。

每一項單獨看都有價值，但第一次使用者會在還沒理解核心流程前，就先看到大量設定和管理功能。頁首橫幅、本局摘要、下方實際設定之間也存在部分資訊重複。

## 設定頁簡化方向

### 推薦資訊層級：快速開局優先，進階功能漸進揭露

第一層「開局必需」預設展開：

- 玩法：多人桌遊／二人棋鐘／自由輪流。
- 玩家與出場順位。
- 主要時間：每回合時間；棋鐘總時間制選定後顯示每人總時間。
- 固定可見的「開始對局」。

第二層「更多計時設定」預設收合：

- 每回合制／總時間制的進一步說明。
- 自訂時間。
- Fischer 加秒。
- 倒數提醒。
- 超時自動換人。

但會改變核心計時規則的控制不可藏得毫無提示。收合列上必須顯示目前摘要，例如：

> 更多計時設定　剩 10 秒提醒 · 手動換人

棋鐘總時間制則例如：

> 更多計時設定　Fischer +2 秒 · 旗倒結束

第三層「常用內容管理」預設收合或移出主流程：

- 已經有常用組合時，可在頁面上方保留精簡橫向捷徑。
- 完全沒有常用組合時，不需要先展示一個空的管理區；改在設定完成附近提供「儲存為常用組合」。
- 常用玩家的主要價值是在改名時一鍵帶入，因此主設定頁不必常駐完整名單與刪除鈕。
- 主頁只保留「管理常用玩家」入口；實際選人仍在改名對話框中出現。

### 頁首與摘要減量

FABLE5 請比較下列做法，提出推薦：

- 保留兔咪橫幅，但把本局摘要縮成一行可掃讀摘要。
- 保留完整本局摘要，但縮小兔咪橫幅高度與文案。
- 合併為一張「兔咪＋本局摘要」卡，避免連續兩張大型卡片。

建議優先考慮合併，並確保首屏或一次短捲動內可以看到玩法、玩家以及開始對局，而不是只看到裝飾與摘要。

### 不建議的簡化方式

- 不要直接刪除常用組合、常用玩家、Fischer 或自訂時間等現有能力。
- 不要把全部設定塞進另一個很長的 bottom sheet。
- 不要讓「簡易／進階」變成兩套互相不同步的設定資料。
- 不要因為收合而讓使用者不知道目前實際套用的提醒、加秒或自動換人規則。
- 不要讓使用者進入全螢幕對局後才發現關鍵規則設錯。

## 建議的設定頁文字 wireframe

## 對局可靠性改善

設定頁 UX 是本輪新增重點，但以下可靠性問題仍應納入整體計畫。FABLE5 可建議拆成不同 commit 或不同階段，避免一次改動過大。

### P0：計時與結算正確性

1. 用 monotonic clock／可測試的單調時間來源取代直接依賴牆鐘時間，避免系統校時造成倒數跳動。
2. 建立正式的結束流程，明確處理結束當下尚未完成的半回合；結算不可讓實際思考很久的玩家顯示成「沒輪到」。
3. 同一次 tick 同時跨入提醒區與最後數秒區時，只發最高優先級提醒，避免音效與震動重疊。
4. 檢查 `inactive`、`hidden`、`paused` 的生命週期策略，任何中斷都不能偷走對局時間。

### P1：對局理解與誤觸救援

1. 骰盤覆蓋對局時，保留目前玩家與剩餘時間的迷你資訊；計時繼續就不能把時間完全藏住。
2. 多人模式換人後提供短暫、直接的「復原」入口，不必先找到暫停面板。
3. 開局前評估提供起始玩家選擇或隨機起始玩家。
4. 結算頁區分已完成回合與結束時未完成回合，避免錯誤的最快判定。

### P2：無障礙、效能與耗電

1. 為多人整面觸控區、棋鐘兩側、拖曳與純圖示按鈕補齊 Semantics 與 Tooltip。
2. 支援系統減少動態效果。
3. 暫停、結束、骰子靜止時停止不必要的 Timer／Ticker。
4. `WakeGuard` 儘量只在真正需要保持亮屏時持有。

## 分階段執行建議

不要把設定頁重構、排序互動、引擎計時與全螢幕對局全部塞進一個巨大 commit。

### 階段 1：先確認 UX 決策

- 比較排序方案 A／B／C 或新的 D。
- 比較設定頁簡化方案。
- 提交文字 wireframe 與狀態轉換說明。
- 等使用者選擇。

### 階段 2：設定頁與排序

- 修正排序文案／圖示／實際手勢不一致。
- 實作確認後的排序模式。
- 重整設定頁資訊層級與收合區。
- 保持既有設定資料、常用組合與常用玩家相容。
- 補 Widget 測試與小螢幕／鍵盤回歸測試。

### 階段 3：引擎可靠性

- 單調時鐘。
- 正式結束與未完成回合統計。
- 提醒事件去重。
- 生命週期測試。

### 階段 4：對局 UX、無障礙與效能

- 骰盤迷你計時資訊。
- 快速復原。
- Semantics、減少動態效果。
- Timer、Ticker、WakeGuard 節流。

每個階段完成後都應先呈現變更摘要與驗證結果，再進入下一階段。若實機／截圖顯示原方案不理想，應停下提出修正，不要為了完成清單硬做到底。

## 驗收標準

### 玩家排序

- 畫面文字、圖示與實際可拖曳區一致。
- 第一次使用者不需猜測 `≡`、點點圖示或長按哪裡。
- 仍可正常改名、刪除、新增與調整順位。
- 2 人、4 人、6 人及棋鐘候補名單都能正確排序。
- 排序後立即保存，重進頁面順序不變。
- VoiceOver／TalkBack 能理解「玩家、目前順位、移動」操作。

### 設定頁減量

- 預設畫面優先看到玩法、玩家、時間與開始對局。
- 進階設定收合時仍看得到目前生效規則摘要。
- 既有常用組合、常用玩家、自訂時間、Fischer、提醒與自動換人均未遺失。
- 空狀態不展示沒有內容的大型常用組合區。
- 鍵盤開啟、SE 尺寸、大字體與 Pro Max 尺寸不切斷內容或銷毀輸入狀態。

### 可靠性

- 系統時間改變不造成計時跳動。
- 結束時的未完成回合有清楚且一致的統計規則。
- 提醒事件不重疊。
- 進背景或被中斷後不偷跑時間。
- 骰盤開啟且計時繼續時，使用者仍看得到目前時間。

## 測試要求

- 更新 `test/table_setup_panel_test.dart`，不可只把舊文案 expectation 換掉；要測實際排序入口、模式切換、保存與收合狀態。
- 新增排序模式的 Widget 測試：長按入口、`⋯ > 移動`、拖曳、完成、棋鐘候補。
- 保留並擴充 `test/game_timer_compact_test.dart` 的鍵盤與高度門檻回歸。
- 擴充 `test/table_timer_engine_test.dart`：單調時間、結束半回合、事件去重、暫停／恢復。
- 新增 `TableStagePage` 流程測試：生命週期、退出確認、骰盤覆蓋、結算與再來一局。
- 完成後執行格式化、單元／Widget 測試、`flutter analyze`、`scripts/check_units.sh`。
- 若改動畫或版面，需用至少一個小螢幕與一個大螢幕尺寸做視覺檢查。

## 不可破壞的既有行為

- 多人模式整個主畫面點擊換下一位。
- 棋鐘上下分割、點自己那側交棒給對方。
- 自由輪流正數計時。
- 即改即存、常用組合與常用玩家資料相容。
- 鍵盤出現時不得因高度門檻切換而銷毀設定面板 state。
- 骰盤覆蓋對局時，除非使用者另行選擇，不應偷偷改變目前既定的計時規則。
- 兔咪仍使用既有高品質 PNG／CG 差分，不改走 Rive 或臉部 overlay。
