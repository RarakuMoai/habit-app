- **想改台詞** → 共用的在 `lib/utils/mascot.dart` 的 `_lines` / `_homeTapLines`；

- **想新增事件** → 照最下方的「新增或修改事件時的檢查清單」。
- **想知道哪些還要處理** → 看「狀態圖例與待辦」。

本目錄不收一般按鈕、表單、SnackBar、通知與狀態卡文案；那些是介面說明，

## 執行規則

1. App 冷啟動只從 `openApp` 抽一句。若首頁要顯示當日個人化問候橫幅，會先把這句收掉，避免兩句重疊。
2. 一般互動至少停留 5 秒；優先度更高的事件可以蓋過它。
3. 互動後 10 秒回到「安靜待機」，不再重抽開場問候。
4. 高頻情境預設不顯示文字，只用情緒圖、符號泡泡與 SFX；呼叫端明確傳入 `speech` 時例外。
5. 直接互動語音有 7 秒冷卻，日常事件語音有 18 秒冷卻；全完成、連勝、撤銷與高量喝水提醒會突破冷卻。
6. **三種聲音管道職責不重疊**（2026-08-04 One-Habit Hero 定案）：SFX 說「事情發生
   了」，對齊使用者看得到的完成事實；haptic 說「份量」，它不是獨立設定，而是由
   SFX cue 推導（`_defaultHaptic`：`complete` → medium、`success` → light、
   `cancel` → selection，所有 `tumi*` 語音 cue 一律 `none`）；語音說「兔咪的心情」，
   晚一拍、跟泡泡同步。**不要給語音配震動**，三個管道擠在同一幀會變吵、讀不出層級。
7. **安靜是正式回饋，不是漏做。** 規則 4 的「高頻不出文字」是這條的延伸：事件愈常
   發生，愈要留白。連續完成時不重複開口，讓 SFX 自己說話。
8. **撤銷要接手，不是並存。** `undone` 發生時，前一個正向語意連同已經在畫面上的
   泡泡與台詞必須讓位，不能兩句同時存在。（`undone` 不配泡泡是刻意的——汗滴是
   尷尬，跟心疼打架。）

**情境判斷順序**（同一頁多個條件時誰優先）：
- 首頁 `home_page._mascotContext`：撤銷 → 點擊台詞 → 無習慣 → 全完成（連續 ≥7 走 `streak`）→ 過半 → 完成一件 → 夜晚 → 未開始。
- 喝水頁 `water_page._mascotCtx`：**過量優先於達標** → 達標 → 零杯 → 過半 → 完成一杯。

**互動之後回到哪**（2026-08-06 補；原本沒定義，導致「點兔咪把牠點睡了」）：

反應演出結束後會回到 baseline，而首頁零進度的 baseline 是 `notStarted` ＝ **睡眠**。
所以點擊／摸頭的收尾原本會把兔咪從中性臉丟回打瞌睡——使用者做了動作，角色卻睡著。

規則：**有動作就醒來。**

- 使用者**主動互動過**（點兔咪、摸頭）之後，首頁零進度的待機立繪改用**中性臉**，
  不再是睡眠。情境本身仍是 `notStarted`（台詞「還沒開始也沒關係」等照舊），
  **只換立繪**。
- 夜晚（22:00–06:00）不受影響，仍走 `night`——那是「真的該睡了」，不是「懶懶等你」。
- 跨日重置時清掉醒來狀態：新的一天還沒碰過，兔咪回到打瞌睡等你。
- 睡眠姿因此保留給「這一天還沒被碰過」，符合角色設定的「懶懶等你」而不是「被吵醒又睡回去」。

`test/mascot_wake_on_tap_test.dart` 在守這條。

### 「我有看到」的處理原則

這句話的毛病不是不夠具體，是**它在宣告而不是證明**：說「我有看到」需要你
相信兔咪；講出實際發生的事就不用。而且「看到」是視覺動詞，使用者知道它是
程式，會有表演感。

處理成三種，避免換成另一種單一句型：

| 情況 | 怎麼改 | 例子 |
|---|---|---|
| 講當下的事 | 換成事實陳述 | 「做到了，我有看到。」→「這件做完了。」 |
| 講過去的事 | 換成「記得」 | 「昨天也完成了。\n我有看到。」→「\n我記得。」 |
| 受詞本來就明確 | **保留** | 「嗯，我有看到你。」「我有看到你一路做到這裡。」 |

「記得」比「看到」有份量：看到是當下的動作，記得是持續的關係——而且
app 的本質就是記錄，兔咪說記得是實話不是表演。這也正好對上角色設定的
「替使用者記得小努力」。

### 為什麼報到卡要「遞零食」

原本的 CTA 是中性的「開始吧」，幣像是系統憑空發的。改成遞零食之後：

> 你給零食 → 兔咪高興 → **足跡幣才出現**

幣因此變成「你和兔咪關係的產物」，而不是打卡報酬——這也讓其他來源的幣
（完成習慣、里程碑）有了一致的解釋。

**沒有增加任何步驟**：本來就要按那顆按鈕，只是按鈕的意義變了。使用者不可能
「忘記餵」，所以不會有電子雞式的罪惡感（roadmap 核心原則：避免帶來額外壓力）。

演的是**收下**不是**吃掉**——兔咪嘴巴永遠不變是人設鐵則，開心只能靠身體彈跳
與歡呼聲表達。減少動態時跳過飛行，直接給回饋後關頁。

### 帶件數的回應（`MascotLines.doneCountLine`）

進度中的情境不再說「我有看到」——那只是宣告自己在看，講得出第幾件才是
證明真的在數。用 `done % 3` 挑句，同一個數字永遠同一句（不會抖動）：

- 第 1 件：「今天第一件。」
- 之後：「數到第 3 件了。」／「已經 4 件了。」／「今天第 5 件。」

**刻意不講總數**（「3/5」是系統通知口吻，兔咪只數你做到的）。
出現時機只有兩個：**今天打卡的第一件**、**首頁點兔咪且進度在進行中**。
打卡是高頻動作，其餘次數維持只有符號＋音效的安靜模式。

## 審稿清單

- 日常直接對話是否用「我」或省略主詞？初遇本名介紹／暱稱確認依角色指南例外，其餘不突然自稱名字。
- 句子是否回應當下事件，而不是任何時候都能插入的「我在」？
- 是否把等級、數值、警告或專業建議說得像系統通知？這類資訊應交給 UI。
- 是否帶有責備、命令、績效評分或過度激勵？
- 同一操作是否同時觸發兩句，或在 10 秒後又無緣無故補一句？
- 夜間、撤銷、回歸等敏感情境是否過度推測使用者的情緒？
