# Apple 隱私要求與兔咪資料規劃

查證：2026-09-18。適用本輪 beta 程式盤點；這是決策文件，不是對外隱私政策。
Apple 上架規則和各地法律是不同層次；法律範圍需依上架地區、使用者年齡及資料用途確認。

## 個人開發者的基本要求

- 可以個人身分加入 Apple Developer Program；App Store 賣家名稱顯示法定姓名。
  不必為一般 App 先成立公司。[Apple 註冊說明](https://developer.apple.com/programs/enroll/)
- 所有 App 都須有可從 App 及商店資料找到的隱私政策，說明資料用途、第三方、保存／刪除與撤回方式。
  必須使用與實際行為一致的內容；測試說明不能替代正式政策。
  [Apple 上架準備](https://developer.apple.com/app-store/review/)
- 未自訂 EULA 時，Apple 標準 EULA 自動適用；這不取代 App 自己的隱私政策。
  [Apple EULA 說明](https://developer.apple.com/help/app-store-connect/manage-app-information/provide-a-custom-license-agreement/)
- App Store Connect 的隱私標示須包含所整合第三方的實際收集行為。
  [隱私資訊填寫](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy)
- 有建立帳號功能時，App 內須可發起刪除帳號及相關資料；停用或登出不能代替。
  [帳號刪除要求](https://developer.apple.com/support/offering-account-deletion-in-your-app/)

Apple 要求用途必要、資料最少化與適當同意；沒有「所有 iOS App 開場一定要兩個必勾框」的規定。
閱讀政策不代表同意全部未來用途。Google 登入另涉及 4.8 的等效隱私登入選項；
目前 Google＋Apple 的方向合理，真實服務仍需配置驗證。健康／高度管制或要求敏感資訊的服務
另涉及 5.1.1(ix) 法人條件，不能因為個人可註冊便忽略；兔咪宜維持日常記錄定位，
是否上傳健康資料需另行評估。[App Review Guidelines 4.8、5.1](https://developer.apple.com/app-store/review/guidelines/)

## App 在手機使用資料，不等於開發者拿到資料

Apple 隱私標示將只在裝置處理的資料，與傳出裝置並由開發者／合作方保存的資料分開。
開啟雲端備份後，要重新盤點實際傳送內容；「玩家選擇上傳」不代表可以省略隱私揭露。
[App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/)

本輪程式盤點：

| 資料 | 現有用途／路徑 | 建議 |
| --- | --- | --- |
| 語言 | 本機 UI 偏好 `AppLocaleSettings` | 可直接沿用系統，讓玩家確認 |
| 生日 | 個人資料；喝水與體重相關功能讀取出生年計算年齡；備份白名單包含生日 | 保留選填；若只為祝福，可評估僅月日；改存格式前須處理既有年齡計算 |
| 玩家／兔咪暱稱 | 故事稱呼、個人資料 | 不需要真實姓名 |
| UID、email、顯示名稱、provider | Firebase 登入 adapter 可讀；服務尚未啟用 | 為登入與跨裝置辨識使用，不直接當行銷名單 |
| 習慣／故事／體重／家庭等紀錄 | 本機偏好；使用者可匯出或手動備份到 Firestore | 備份是恢復用途，不能直接挪作產品分析；需決定家庭／健康資料上傳範圍 |
| 功能使用次數 | `UsageStats` 本機事件日計數；沒有獨立分析上傳；但 `usageDayPrefix` 在備份白名單內 | 不能宣稱永遠不上傳；也不應把帳號備份拿來當分析資料集 |
| 當機與效能 | 本輪 pubspec 無 Firebase Analytics／Crashlytics | 可先評估 Apple 提供的彙總資料，再決定是否加收集服務 |

程式已有帳號刪除 adapter，含 Apple token 撤銷、備份刪除與防重建 tombstone；
這只是程式現況，不代表真實後台刪除已驗收。刪除政策還需說明 tombstone 保存目的及期限。

## 建議的資料用途分組（待本人決定）

1. **陪伴／功能**：暱稱、生日、習慣與故事進度，優先在裝置使用。
2. **恢復**：登入與玩家明確選擇的備份內容，用於換機／還原。
3. **產品改善**：例如功能開啟、故事完成率、錯誤碼與版本。若未來上傳，獨立說明、選擇與撤回，
   不附帶暱稱、完整生日、email、習慣內容或體重數值。匿名名稱不自動等於真正匿名。
4. **廣告／行銷**：目前未實作或授權。跨公司 App／網站追蹤涉及 ATT，與一般分析不同。
   [Apple 追蹤定義](https://developer.apple.com/app-store/user-privacy-and-data-use/)

Apple 既有分析可提供部分彙總使用與診斷資訊，來源受使用者分享選擇及隱私措施限制；
它不能替代兔咪專有故事事件的設計。
[Apple App Analytics 隱私說明](https://www.apple.com/legal/privacy/data/en/app-analytics/)

## 已收到的產品方向

- 使用者明確希望全年齡都能使用；未成年使用者須納入規劃，不等於已決定選擇 Kids Category。
- 除功能／故事使用情況，使用者也想知道大致年齡層與地區。
- 建議年齡僅以區間、地區以國家／地區呈現；完整生日留在手機，不為統計新增 GPS 權限。
  若依商店地區報表觀察分布，標示為商店地區，不能冒充玩家實際居住地。
  台灣首發若需觀察島內分布，可提議選填北／中／南／東／離島等大區；此細分尚未定案，不新增定位權限。
- 這些是產品需求與建議，尚未授權新增分析 SDK 或收集端點；兒童同意方式、匿名／去識別化設計、
  保存期限仍須決定。首發市場已確定為台灣。

## 優先討論

- 全年齡方向已確認，接續釐清兒童是否主要行銷對象與兒童模式／家長流程。
  年齡分級、Kids Category、家長同意與資料收集不是同一件事。
  Apple 的年齡範圍 API 可以提供範圍而不給完整生日；是否適用須依目標市場與平台確認。
  [Apple 兒童與年齡體驗](https://developer.apple.com/kids/)
- 功能／故事使用情況、大致年齡層與地區已確認為需求；先定義要回答的問題，
  才挑資料欄位與服務；不為「可能用到」全面收集。
- 首發台灣已確認；正式資料流程需依台灣個資要求及未成年情境完成，不預先套用全球市場方案。

對外政策定稿前還需：開發者聯絡方式、公開政策網址、收集服務及所在地、各資料保存期限、
刪除／撤回入口、備份範圍、兒童定位。技術上另核對最終打包的 SDK 隱私清單及 required-reason APIs；
`PrivacyInfo.xcprivacy` 並不代替政策或商店標示。
[Apple privacy manifests](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files)

## 功能使用情況與題型

使用者提醒資料需求應可複選，並強調功能頁使用情況很重要；
功能使用率、故事進度、年齡層、地區均納入規劃，不視為互斥選項。

| 要回答的問題 | 建議來源 | 不需要一起取得的內容 |
| --- | --- | --- |
| 六個功能頁各有多少人使用、多久回訪？ | 經適當告知／同意的頁面與使用日統計；區分使用人數與點擊次數 | 精確路徑時間線、可識別帳號 |
| 開了功能後有沒有做完？ | 打卡完成、計時完成／取消、喝水與體重記錄成功、衣櫃套用等事件計數 | 習慣文字、喝水量、體重值、家庭成員姓名 |
| 故事在哪裡停止？ | 章節 ID 的開啟／完成／略過彙總 | 玩家輸入內容與暱稱 |
| 年齡層與地區分布？ | 非必要的單選區間／地區或適用的商店彙總；兒童資料另行設計 | 完整生日、精確地址、GPS |
| 玩家對哪些功能有興趣？ | 可略過的複選問卷 | 強制先選功能才能進故事 |

目前 `UsageEvents` 已有六頁開啟、打卡、喝水／體重新增、計時啟動、衣櫃購買／套用、
回憶等本機次數；計時啟動包含 resume，不能直接當成新開一場的次數。
尚未因此擴增追蹤或接入服務。未來同意率、樣本數與兒童資料缺口要明列，不能拿有分享的樣本
直接當作所有玩家的完整人口分布。

## 台灣首發須具體補齊的資訊

台灣《個人資料保護法》中的非公務機關包含自然人；個人製作不是當然豁免。
資料蒐集告知應交代蒐集者、目的、類別、使用期間／地區／對象／方式、權利行使及不提供的影響。
引用依第 2、3、5、8 條；官方頁面另標示部分 114 年修法尚未施行，本輪不把那些條文誤列為已生效要求。
[主管機關法規來源](https://law.pdpc.gov.tw/LawContent.aspx?id=FL010627)

後續實作前先定好資料字典、保存期限、同意／撤回與未成年流程，再完成正式政策；
新資料用途不能只靠前導一次閱讀確認無限延伸。
